# Security review

Scope: everything under `/api/v1/connect/`, the Connect pages, the equipment-page Discussions tab, notifications and email, attachments, search, analytics and the background tasks.

## Threats and controls

| # | Threat | Control | Evidence (tests) |
|---|---|---|---|
| 1 | Anonymous access, public indexing | All views need DRF token auth. Responses send `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`. Pages add a noindex meta tag. `robots.txt` disallows `/connect` and `/api/v1/connect/`. | `test_m13_security::test_unauthenticated_is_rejected_everywhere` (crawls 50+ routes with all methods), `test_responses_are_private_and_noindex` |
| 2 | Module off or pilot-only | `ConnectEnabled` answers 404 on every endpoint except the bootstrap; signals and tasks do nothing. | `test_flag_off_hides_everything_but_bootstrap`, `test_pilot_list_excludes_unlisted_users`, `test_signal_is_noop_when_flag_off` |
| 3 | Cross-group access (IDOR, guessed IDs and slugs) | Objects are loaded only through `access.visible_*`, so another group's object is a 404. UUIDs for attachments; sequential IDs give nothing away. | `test_group_b_never_reaches_group_a_objects` (14 reads and 15 writes, ×3 user kinds), plus per-milestone cross-group tests |
| 4 | Leakage via lists, counts, search, suggestions, tags, home, analytics, notifications, drafts, equipment panel | Every aggregate starts from the caller's readable communities or threads. Search matches only *visible* text, for moderators too. Tag counts are over readable threads. Search insight is admin-only with a minimum count of 3. | `test_group_b_lists_counts_search_and_home_never_mention_group_a`, `test_tag_list_never_leaks_other_group_tags`, `test_other_group_content_never_matches`, `test_hidden_or_deleted_reply_text_is_not_searchable`, `test_analytics_only_for_moderators_and_scoped`, `test_search_insight_is_admin_only_with_threshold` |
| 5 | External users seeing internal content | General is readable only by IITR internal users; externals see only their booked groups. Mention suggestions in General never offer externals. | `test_external_users_never_see_general`, `test_external_user_never_reaches_general`, `test_mention_candidates_limited_to_readers` |
| 6 | Stored XSS | Server: nh3 allowlist (no `style` or event attributes; links http(s) and mailto only, with `rel` noopener nofollow ugc; images only as attachment IDs, never a `src`). Client: DOMPurify again. Search snippets are HTML-escaped before `<mark>` is applied. Email values are escaped before template substitution. | `test_sanitiser_blocks_xss`, `test_body_is_sanitised`, `test_snippet_never_carries_markup_from_user_text`, frontend `sanitises post HTML a second time` and `shows only <mark> from the snippet` |
| 7 | Malicious uploads | Size limit; type sniffed from content (images, PDF, Office, text and CSV only). Executables, HTML and SVG are refused. Files are stored privately and streamed with `nosniff`, `no-store`, a sandboxing CSP and attachment disposition (inline only for images and PDF; text never inline). Uploads bind only to the uploader's own post in the same community. Unbound uploads are purged after 24 h. | `test_upload_type_and_size_validation`, `test_text_attachment_never_served_inline`, `test_cannot_bind_someone_elses_or_foreign_upload`, `test_attachment_upload_bind_download_and_isolation`, `test_purge_removes_only_old_unbound_uploads` |
| 8 | Privilege escalation | Badges come from assignments only. Moderators cannot suspend staff or themselves. Community Admins are appointed by the Portal Admin only. Reviewers cannot approve their own articles. Cross-community moves are admin-only and need `confirm_widen`. Announcements are staff-only. | `test_moderator_can_suspend_member_but_not_revoke_or_touch_staff`, `test_community_admins_by_portal_admin_only`, `test_full_workflow_with_four_eyes_review`, `test_admin_move_across_communities_needs_confirmation`, `test_only_staff_post_announcements_with_settings` |
| 9 | Access widening through articles or moves | An article copies its source thread's community and it can never change. A move is audited and confirmed. | `test_only_curators_promote_and_article_inherits_community` |
| 10 | Notification leakage | Recipients are re-checked at creation and at email or digest time. Mentions resolve only to readers. Bodies are never included (title, community and link only). | `test_no_notification_after_losing_access`, `test_daily_digest_rechecks_access`, `test_immediate_email_has_title_and_link_only`, `test_in_app_uses_the_portal_bell_without_post_bodies` |
| 11 | Spam and abuse | Per-user throttles (read, write, post, upload, search, report); duplicate text within 5 minutes refused; at most 20 links; optional minimum account age; automatic hide after 3 distinct reporters; reactions on your own post refused. | `test_validation_and_duplicate_protection`, `test_report_rules_and_auto_hide`, `test_reactions` |
| 12 | Manipulated recognition | Self-accepts excluded; helpful marks count each distinct person once; only visible content counts; badges are withdrawn when the evidence disappears; off by default. | `test_self_accepted_answers_do_not_count`, `test_helpful_counts_distinct_people_once`, `test_badges_come_from_accepted_answers_not_volume` |
| 13 | CSRF | The API uses the `Authorization: Token` header only, and the SPA sends `credentials: "omit"`. No cookie-authenticated Connect endpoint exists, so CSRF does not apply. | (design) |
| 14 | Effects on operations | No Connect code writes bookings, slots, payments, wallets or equipment. Discussion data is never used as availability. | `test_accepting_never_touches_equipment`, `test_staff_flags_are_moderator_only_audited_and_never_touch_equipment`, `test_announcements_never_touch_bookings` |
| 15 | Public equipment page | The Discussions tab mounts only in the signed-in `EquipmentProfile`. The public QR page and its endpoint are unchanged. | `test_public_equipment_page_never_carries_connect_content`; browser check: signed out, no tab, no text and no Connect request |

## Residual risks and notes

- **No malware scanning.** File checks validate the type only; the portal has no scanner. Office files are always served as downloads.
- **Admins moving a thread to another community** deliberately widens its readers, including its attachments. It needs `confirm_widen` and is audited.
- **Existence of a group is not secret.** On an equipment page, a non-member learns only that the instrument's group has a community; no titles or counts are shown. Group names are already visible in the catalogue.
- **The pilot list is matched by email (case-insensitive).** Users whose email changes need the list updated.
- **Search terms are stored** (`ConnectSearchLog`, normalised) for analytics. They are shown only to admins, aggregated with a minimum of 3. No retention purge is implemented yet (see known-limitations).
