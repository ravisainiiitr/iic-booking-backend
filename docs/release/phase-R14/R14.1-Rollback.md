# R14.1 — Rollback

Use this only after R14.1 has actually been deployed. As of 2026-08-14, production is still **v2.5.40-r13-ghost-reserved** and 0188 has **not** been applied.

## Versions

| Role | Version |
| --- | --- |
| Previous healthy production | `v2.5.40-r13-ghost-reserved` (`origin/master` `f8c0892`) |
| Intended R14.1 tag | `v2.5.41-r14-auto-complete-ra-data-selection` (not created in this session) |
| Schema change | `0188_equipment_auto_complete_and_data_selection` |

## Schema compatibility

0188 is additive:

- `equipment.auto_complete_booking` BooleanField `default=False`
- `booking.analysis_data_selection` JSONField `default=dict`

Rolling **application code** back to `v2.5.40-r13-ghost-reserved` **while leaving 0188 applied** is compatible: old code ignores the extra columns; Django does not require dropping them.

Do **not** roll back application code to a build that expects those columns to be absent **and** then reverse 0188 if newer code is still running.

Do **not** reverse 0188 while R14.1 code is still deployed (the running app would query missing columns).

## Rollback procedure (after a failed R14.1 deploy)

1. Stop. Do not make ad-hoc production SQL edits.
2. Diagnose using container logs, `showmigrations equipment`, and `/api/v1/analysis/health/ready/`.
3. Redeploy previous healthy backend tag via **Deploy Backend** with `release_tag=v2.5.40-r13-ghost-reserved`.
4. Redeploy previous frontend `master` SHA `83d38f7` (or the frontend tag/commit that was live before the R14.1 merge).
5. Leave 0188 in place unless a schema reverse is explicitly required. If reverse is required:
   - Confirm no running process still writes `auto_complete_booking` / `analysis_data_selection`
   - Apply reverse only through `manage.py migrate equipment 0187` (back to PI migration) via the existing migrate workflow, not manual DDL
6. Re-check health ready/live.
7. Leave Auto Complete OFF on all equipment.

## If migrate 0188 fails

Do not continue frontend deploy. Restore the previous backend image/tag. Do not hand-edit `django_migrations` or equipment/booking tables.

## Auto Complete

Enabling Auto Complete is a per-equipment portal setting, not a migration default. Rollback of enablement is: set **Enable Auto Complete Booking** to OFF on any equipment that was turned on. In this session none were enabled.
