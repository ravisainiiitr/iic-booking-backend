# R.2.3 — Trusted Department Auto-Approve

**Status:** Implemented (DSA only)  
**Scope:** Architecture + Backend + Security + DSA installer handoff  
**Does not modify:** Equipment PC Wizard, Remote Analysis Agent (R.2.4 / R.2.5)

---

## Objective

For trusted departmental deployments, Department Sync Agent install completes as:

```
Install → Login → Finish
```

without a second administrator approval click in the portal.

Administrator authentication remains mandatory. Auto-approval never bypasses login.

---

## Architecture

```mermaid
sequenceDiagram
  participant Inst as DSA Installer
  participant Loop as 127.0.0.1 listener
  participant Portal as Portal API
  participant Policy as DepartmentProvisioningPolicy

  Inst->>Loop: Start loopback HttpListener
  Inst->>Portal: Open /device-provisioning/installer-auth
  Note over Portal: Admin signs in (Portal / Channel-i)
  Portal->>Loop: Redirect with Token + department_id
  Inst->>Portal: POST /api/v1/provisioning/sessions/\nAuthorization: Token …\ndevice_type=dsa + fingerprint + department_id
  Portal->>Policy: Evaluate mode
  alt TRUSTED_AUTO_APPROVE (gates pass)
    Policy-->>Portal: allow
    Portal-->>Inst: status=approved, session_proof
    Inst->>Portal: POST …/claim/
    Portal-->>Inst: device UUID + access_token (once)
  else MANUAL / network fail / insufficient rights
    Policy-->>Portal: deny
    Portal-->>Inst: status=pending
    Note over Inst,Portal: Admin approves in Pending Installations
    Inst->>Portal: claim after approved
  else DEVICE_CODE
    Portal-->>Inst: device_code + pending
    Note over Portal: Admin approves via Approve by code
  end
```

### Components

| Layer | Change |
|-------|--------|
| Model | `DepartmentProvisioningPolicy` (+ session auto-approve / device_code fields) |
| Service | `policy.py` evaluation + `create_session(..., actor=)` |

## Provisioning modes

| Mode | Behavior |
|------|----------|
| **MANUAL_APPROVAL** | Always Pending until portal Approve |
| **TRUSTED_AUTO_APPROVE** | Auto-approve when auth + dept membership + Dept Admin+ + fingerprint + no duplicate active identity |
| **RESTRICTED_AUTO_APPROVE** | Same as Trusted **plus** client/local IP in allowed CIDR list; else Pending |
| **DEVICE_CODE** | Installer shows `XXXX-XXXX`; admin approves from another browser |

### Default policy

- **New departments** (signal): `TRUSTED_AUTO_APPROVE` (IIT Roorkee default).
- **Existing departments** without a policy row: on first **authenticated** session create,
  portal lazy-creates `TRUSTED_AUTO_APPROVE` (same default). Explicit Manual / Restricted /
  Device Code rows are never overwritten. Unauthenticated creates remain Pending.

---

## Auto-approval gates

Portal auto-approves **only** when all hold:

1. Administrator authenticated (`Authorization: Token …`)
2. Administrator belongs to target department (Main Admin may any dept)
3. Administrator has provisioning rights (`admin` / `dept_admin` / `manager`)
4. Device fingerprint present (when `require_device_fingerprint`)
5. No duplicate **active / provisioning / suspended / pending_approval** device with same fingerprint
6. Policy mode is Trusted or Restricted (and network OK for Restricted)
7. If `require_mfa` and portal MFA not satisfied → **Pending** (secure default until MFA is wired)
8. Revoked reinstall: allowed when `auto_approve_existing_reinstalls` (default true)

Otherwise → **Pending Approval** (or **409 duplicate_active_device** when an active identity already exists).

## Security model

| Control | Rule |
|---------|------|
| Authentication | Mandatory for auto-approve; anonymous create stays Pending |
| Bootstrap / session proof / access token | Single-use or short TTL; hashed at rest; never logged; never shown in admin UI |
| Admin Token | Installer memory only; cleared after session create / claim path |
| Audit | No secret keys accepted into `DeviceAuditLog.detail` |
| MFA | `require_mfa=True` forces Pending until server-side MFA attribute exists |
| Scope | DSA only in R.2.3 |

### Audit events

| Action | When |
|--------|------|
| `provisioning_started` | Session registration |
| `policy_used` | Policy evaluation (mode, allow, reason, dept, fingerprint, admin) |
| `auto_approved` | Trusted/Restricted success |
| `auto_approve_denied` | Soft deny → Pending (reason recorded) |
| `approved` / `provisioned` | Manual / claim path (unchanged) |

## Department policy configuration

**UI:** Portal → Device Provisioning → **Device Provisioning Policies**

**API:**

- `GET /api/v1/provisioning/policies/`
- `GET|PUT /api/v1/provisioning/policies/<department_id>/`
- `POST /api/v1/provisioning/pending/approve-by-code/` `{ "device_code": "XXXX-XXXX" }`

Fields: mode, allowed_networks (CIDR list), require_mfa, require_device_fingerprint, maximum_pending_lifetime_hours, auto_approve_existing_reinstalls, audit_enabled.
