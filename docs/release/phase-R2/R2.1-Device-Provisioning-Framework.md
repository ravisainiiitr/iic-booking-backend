# Device Provisioning — Phase R.2.1

Unified portal framework for **all** device types (DSA, Equipment PC, Remote Analysis, and future GPU / AI / IoT).  
Installers are **not** changed in R.2.1 — only the portal control plane + admin UI.

## Lifecycle

```
Unknown Device → Pending Approval → Provisioning → Active → Suspended → Revoked → Retired
```

One subsystem — no per-product enrollment engines.

## Models

| Model | Role |
|-------|------|
| `ProvisioningSession` | Installer registration / Pending Installations |
| `ProvisionedDevice` | Authoritative device UUID + lifecycle |
| `DeviceBootstrapToken` | Single-use, short TTL, hashed |
| `DeviceCertificate` | Future mTLS (stub) |
| `DevicePolicy` | Type- or device-scoped JSON policies |
| `DeviceInventory` | Snapshots |
| `DeviceHeartbeat` | Heartbeat history |
| `DeviceAssignment` | Department / equipment / RAA role (unique equipment) |
| `DeviceAuditLog` | Created / Approved / Rejected / Provisioned / … |

## REST API (`/api/v1/provisioning/`)

| Method | Path | Auth |
|--------|------|------|
| POST | `/sessions/` | AllowAny + throttle — installer register |
| GET | `/sessions/{id}/` | Session proof header **or** admin |
| POST | `/sessions/{id}/claim/` | Session proof — returns pack **once** |
| GET | `/pending/` | Admin |
| POST | `/pending/{id}/approve/` | Admin (never returns secrets) |
| POST | `/pending/{id}/reject/` | Admin |
| PATCH | `/pending/{id}/` | Admin rename / assign dept / equipment / role |
| GET | `/devices/` | Admin |
| GET | `/devices/retired/` | Admin |
| POST | `/devices/{id}/suspend\|revoke\|retire/` | Admin |
| POST | `/devices/{id}/heartbeat/` | Bearer device token |
| GET | `/audit/` | Admin |
| GET | `/console/` | Admin summary |

Installer register body (canonical):

```json
{
  "device_type": "dsa|equipment_pc|remote_analysis|…",
  "machine_guid": "…",
  "hostname": "…",
  "windows_version": "…",
  "cpu": "…",
  "ram_gb": 32,
  "mac_addresses": ["aa:bb:…"],
  "local_ips": ["10.0.0.1"],
  "application_version": "1.0.0",
  "bootstrap_public_key": "…"
}
```

Response includes `session_proof` **once**. Portal stores only the hash.  
Approve creates `ProvisionedDevice` + bootstrap token (hashed).  
Claim returns `device_uuid`, `access_token`, `policies`, `configuration` once.

## Admin UI

Route: `/device-provisioning`

Tabs: Pending Installations · Provisioned Devices · Retired Devices · Audit  

Linked from Dashboard (Deployment Center → Devices) and Deployment Center header.

## Security

- Bootstrap + access tokens hashed at rest (`django.contrib.auth.hashers`)
- Bootstrap TTL 10 minutes; session TTL 24 hours
- Admin approve/reject responses never include tokens
- Audit detail strips secret keys
- Legacy `/api/v1/sync/enroll/` and `/api/v1/analysis/register/` remain for existing agents (deprecated for new standard path; installers unchanged until R.2.2+)

## Migration

```bash
python manage.py migrate device_provisioning
```

Existing DSA / RAA / Equipment PCs are untouched. Optional later: backfill `ProvisionedDevice` rows from legacy tables via `legacy_dsa_id` / `legacy_workstation_id`.
