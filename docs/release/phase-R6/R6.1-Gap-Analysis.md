# R6.1 — Gap Analysis

Compare desired software-centric architecture to the assessed codebase (see [R6.0](R6.0-Current-State-Assessment.md)).

## Desired model

```
Department → Equipment / Remote Analysis PCs / Software Catalog
Equipment → Supported Software   (NOT permanent Equipment → RA PC)
RA PC → Installed Software, CPU, GPU, RAM, Load, Health, Online
Scheduler: Equipment → Supported Software → Best Available RA PC
```

## Classification

| Capability | Classification | Why |
|------------|----------------|-----|
| Software Catalog | **Already complete** (admin + model) | `AnalysisSoftwareCatalog` + Django Admin + installer read API. SPA CRUD optional product polish, not architectural gap. |
| Installed software on RA PC | **Already complete** | Agent/installer → `InventoryService.synchronize` → `InstalledSoftware`. |
| Equipment → Supported Software | **Already complete** | `EquipmentAnalysisSoftware` + `SoftwareMappingService`. Legacy `analysis_profile` still dual-read. |
| Equipment → RA PC permanent bind | **Needs redesign (soft)** | Desired: **not** permanent. Current `EquipmentAnalysisPool` is priority-only (correct). Keep dual-read; do not promote pool to exclusive bind. |
| Auto workstation selection | **Already complete** | `AllocationService.select_best` + `auto_allocate`. Users never pick PC in Workspace/Launch. |
| Scheduler uses installed software | **Needs enhancement** | Matching existed; pre-R6 `ensure_reservation` often required **all** equipment-mapped software names. R6 slice: require **selected** profile/software (workflows still pass multi-name lists). |
| Analysis Workspace filters by equipment software | **Needs enhancement** | Backend `GET .../analysis/software/` existed; UI was display-only and did not POST `software_slug`/`mapping_id`. R6 wires selection. |
| Queue per department+software + ETA | **Already complete** (ops) | `ReservationQueue` + Workspace queue UX. ETA quality depends on telemetry; not redesigned in R6. |
| License types (concurrent/network/unlimited) | **Needs enhancement** | Fields existed as free-text / seats. R6 adds explicit `LicenseType` choices on catalog. Deep license-server integration remains deferred. |
| Software discovery in installer | **Already complete** | Multi-scanner + catalog merge + selection UI. |
| Agent runtime discovery parity | **Needs enhancement** | Runtime still registry-only; installer has richer scanners. Documented; not blocking vertical slice. |
| Admin: Catalog / Eq↔Software / RA Inventory | **Needs enhancement** (UX surface) | Django Admin covers catalog + mapping; SPA has RA inventory read-only. SPA CRUD deferred to avoid duplicate admin. |
| AI-ready metadata | **Needs enhancement** | Workflow AI fields existed; catalog lacked reserved tags. R6 adds `ai_tags` / `ai_metadata` without consumers. |
| GPU load / installer GPU | **Needs enhancement** | GPU **name** reported on agent path; utilization often null; installer GPU blank. Deferred. |
| SPA license management | **Missing completely** (SPA) | Read-only `licensed` column only. Backend ingest exists. Defer SPA CRUD. |

## Priority for implementation (R6)

1. **Highest leverage (done on branch):** selected software → allocation + Workspace selection UI + catalog license/AI metadata.  
2. **Next (deferred):** agent Program Files/Start Menu parity with installer; SPA catalog if operators reject Django Admin.  
3. **Later:** license-server integration; GPU util; AI recommender.
