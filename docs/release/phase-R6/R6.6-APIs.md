# R6.6 — APIs

Mount: `/api/v1/analysis/` (see `config/api_router.py`) plus booking analysis under `/api/v1/bookings/{id}/analysis/`.

## Existing (reuse — do not duplicate)

| Method | Path | Role |
|--------|------|------|
| POST | `/api/v1/analysis/register/` | Agent registration |
| POST | `/api/v1/analysis/heartbeat/` | Load / health |
| POST | `/api/v1/analysis/inventory/` | Software + hardware sync |
| GET | `/api/v1/analysis/software/` | Fleet installed software |
| GET | `/api/v1/analysis/fleet/inventory/` | Fleet inventory |
| GET | `/api/v1/analysis/installer/catalog/software/` | Installer catalog read |
| GET/POST | `/api/v1/analysis/reservations/`, `availability/`, `candidates/`, `queue/`, `scheduler/status/` | Scheduler |
| GET | `/api/v1/bookings/{id}/analysis/` | Workspace summary (`software_options`) |
| GET | `/api/v1/bookings/{id}/analysis/software/` | Equipment-mapped options |
| POST | `/api/v1/bookings/{id}/analysis/analyze/` | One-shot allocate + launch |

Body fields already supported on analyze: `mapping_id`, `catalog_id`, `software_slug`, `workflow_id`, `variables`.

## R6 delta

- **No new public endpoints.** Behavior change is in `ensure_reservation` allocation requirements when a software profile is resolved.  
- Catalog admin remains Django Admin (not a new REST CRUD surface in this phase).

## Provisioning

`/api/v1/provisioning/*` — RA device claim creates workstation + token; inventory remains the analysis inventory API.
