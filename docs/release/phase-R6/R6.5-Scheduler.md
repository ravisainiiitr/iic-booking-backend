# R6.5 — Scheduler

> Note: planning doc `R6.4-Scheduler.md` described the same engine. This R6.1 doc is the operator-facing scheduler reference (user doc index maps **R6.5 → Scheduler**).

## Desired filter / preference order

Practical evaluation order (hard filters then soft score):

1. **Department** affinity (soft score; optional hard pool only with `EQUIPMENT_PRIORITY` rule)
2. **Online** (heartbeat / token)
3. **Healthy** (health score threshold, enabled, not maintenance)
4. **Software** installed (requirement + `required_software_names`)
5. **License** available (expired / seats / concurrent / server configured when required)
6. **CPU** (reject if saturated ≥95%; else soft score)
7. **GPU** (requirement hard; else soft score)
8. **RAM** (requirement hard; else soft score)
9. **Lowest load** (CPU/memory soft score)
10. **LRU / idle** (idle time + recent usage soft score)
